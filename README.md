# Iniity Sovereign AI Agent

| **Version** | **License** | **Maintained by** |
| :--- | :--- | :--- |
| 1.0.0 | MIT | [Iniity Inc.](https://www.iniity.com) |

This project provides a portable, containerized anomaly detection agent by Iniity Inc., designed with data sovereignty and verifiability at its core. It enables users to train and deploy anomaly detection models within their own environments, ensuring that sensitive data never leaves their control.

The agent is built using Python, Docker, and common data science libraries, providing a robust and reproducible environment for anomaly detection tasks.

## Core Concepts

-   **Sovereignty:** Your data and models **never** leave your environment. The agent is a stateless engine that operates on locally mounted volumes. All processing happens locally within the Docker container.
-   **Verifiability:** The codebase can be cryptographically verified against a `sovereign_manifest.json` file (generated via `make manifest`) to ensure it has not been tampered with.
-   **Security:** The environment is hardened by default, using a non-root user within the Docker container, minimal privileges, and a secure base image.
-   **Automation:** A comprehensive `Makefile` and pre-commit hooks automate common developer and operational tasks, from testing and linting to building and running the agent.
-   **Configuration:** Application settings are managed via environment variables (using a `.env` file) and validated with Pydantic for robustness.
-   **API First:** Interact with the agent primarily via a FastAPI-based HTTP API. (CLI interactions are now for script-level tools like integrity verification).

## Getting Started

### Prerequisites

-   **Docker & Docker Compose:** Ensure Docker Desktop or Docker Engine with Docker Compose plugin is installed and running. ([Install Docker](https://docs.docker.com/get-docker/))
-   **Git:** For cloning the repository.
-   **Make:** (Optional, but recommended for using the Makefile)
-   **Python 3.10+:** (For local development outside Docker, or for pre-commit hooks)

### First-Time Setup

1.  **Clone the Repository**
    ```sh
    git clone https://git.iniity.com/IniitySovereignAgent.git # Official Iniity Repo URL
    cd IniitySovereignAgent
    ```

2.  **Install Git Hooks (for developers)**
    This step ensures code quality before you commit. Requires Python and pip.
    ```sh
    pip install pre-commit
    pre-commit install
    ```

3.  **Create Local Configuration**
    Copy the `.env.example` template to `.env`. The defaults are generally ready for local use.
    ```sh
    cp .env.example .env
    ```
    Review `.env` and adjust settings like `INPUT_DATA_PATH`, `MODEL_OUTPUT_PATH`, `MODEL_CONTAMINATION` if you plan to run training/prediction (once those features are fully API-driven).

4.  **Place Your Data (for future ML operations)**
    -   Create a `data/` directory: `mkdir -p data`
    -   Add your dataset (e.g., `dataset.csv`) into this `data/` directory.
    -   Create a `models/` directory: `mkdir -p models`.

5.  **Build and Start the Application Service**
    This command builds the Docker image and starts the application container in detached mode.
    ```sh
    make up
    ```
    The application service (FastAPI) will be running in the background. Access the Web UI at `http://localhost:8000` and API docs at `http://localhost:8000/api/docs`.

### Using the Application

The primary interaction is now through the Web UI (Phase B onwards) and its underlying API. Script-level tools are available via `make` targets or direct execution for administrative tasks.

-   **Access Web UI:** Open `http://localhost:8000` in your browser.
-   **Check Health / API Docs:** Use buttons on the Web UI or access `/api/v1/health`, `/api/docs`.
-   **Code Integrity (via Makefile & Scripts):**
    *   `make manifest`: Regenerates `sovereign_manifest.json` using `scripts/verify_integrity.py generate`.
    *   `make verify-integrity-script`: Verifies codebase against `sovereign_manifest.json` using `scripts/verify_integrity.py verify`.
    *   (The Web UI will also provide buttons for these actions via API calls in later steps of Phase B).

### Developer Workflow: The `Makefile`

The `Makefile` is your primary tool for development and operational tasks.

| Command                   | Description                                                              |
| :------------------------ | :----------------------------------------------------------------------- |
| `make help`               | Show all available Makefile commands.                                    |
| `make up`                 | Build and start all services (application) in detached mode.             |
| `make down`               | Stop and remove all running services.                                    |
| `make logs`               | Follow logs for the `sovereign-app` service.                             |
| `make shell`              | Start a bash shell inside the `sovereign-app` container.                 |
| `make lint`               | Run `flake8` linter on the source code (`src/`, `tests/`).                |
| `make format`             | Format code with `black` (`src/`, `tests/`).                             |
| `make test`               | Run `pytest` for all tests.                                              |
| `make manifest`           | (Re)generate the `sovereign_manifest.json` using the script.             |
| `make verify-integrity-script` | Verify codebase integrity using the script directly.                   |
| `make rotate-secrets`     | Provides guidance and helpers for rotating secrets.                      |
| `make clean`              | Stop services and remove all volumes.                                    |
| `make generate-keys`      | Generate ECDSA signing keys using `scripts/verify_integrity.py`.         |

### Configuration (`.env` file)

Refer to `.env.example` for available options. Key settings include:
| Variable                  | Description                                                                    | Default (in code)                     |
| :------------------------ | :----------------------------------------------------------------------------- | :------------------------------------ |
| `ENVIRONMENT`             | Runtime environment (e.g., `development`, `production`).                       | `development`                         |
| `LOG_LEVEL`               | Logging verbosity (`DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`).               | `INFO`                                |
| `INPUT_DATA_PATH`         | Default in-container path to input data for ML.                                | `/app/data/dataset.csv`               |
| `MODEL_OUTPUT_PATH`       | Default in-container path to save trained models for ML.                       | `/app/models/anomaly_model.joblib`    |
| `DATA_MANIFEST_PATH`      | Path to specific data manifest for `src/main.py verify` (old CLI).             | `/app/data/manifests/default_data_manifest.json` |
| `MANIFEST_OUTPUT_PATH`    | Directory where training process saves data manifests.                         | `/app/data/manifests/`                |
| `APP_NAME`                | Application name for branding.                                                 | `Iniity Sovereign AI Agent`           |
| `COPYRIGHT_HOLDER`        | Copyright holder for branding.                                                 | `Iniity Inc.`                         |

Paths like `/app/data`, `/app/models`, `/app/static`, `/app/templates` inside the container are mapped from your local project directories via `docker-compose.yml`.

### Code Integrity Verification

This project uses `scripts/verify_integrity.py` to generate and check a `sovereign_manifest.json` file, which contains cryptographic hashes of source files and optional ECDSA signatures.

1.  **Generate/Update Manifest:**
    ```sh
    make manifest
    ```
    Commit `sovereign_manifest.json` to your repository.

2.  **Verify Integrity:**
    ```sh
    make verify-integrity-script
    ```
    The application also performs a startup integrity check (see `src/main.py` and `Dockerfile`). The Web UI will provide further integrity status (Phase B2).

### Security Considerations

-   **Non-Root User:** Docker container runs as non-root.
-   **Data Encryption:** `src/agent/encryption.py` provides encryption utilities. Secure key management is crucial for production.
-   **Sovereign Operation Policy:** Refer to `POLICY.md`.
-   **Secret Management:** Use the `make rotate-secrets` target as a reminder and helper for managing secrets. Follow guidelines in `OPERATIONS.md`.
